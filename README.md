# Work-Zilla Notifyer

Локальный веб-инструмент: показывает ваши задания с work-zilla.com и позволяет
скачать `.ics`-напоминание "проверить публикацию" с произвольной датой/временем
для импорта в любой календарь (Google Calendar, Outlook, Apple Calendar и т.д.).

## Установка

```
npm install
copy .env.example .env   (или cp .env.example .env)
```

Заполните `.env`:

- `WORKZILLA_USER_ID` — ваш ID (виден в адресе `/freelancer/<id>`).
- `WORKZILLA_AGENT_ID` — значение заголовка `agentid` из запросов браузера.
- `WORKZILLA_COOKIE` — вся строка `Cookie` из запроса к `client.work-zilla.com`
  (DevTools → Network → любой XHR-запрос → заголовок `Cookie`, скопировать целиком).

Сессия и Bearer-токен в cookie у Work-Zilla — временные и истекают. Когда сервер
начнёт отвечать `401/403`, просто зайдите на сайт заново и обновите `WORKZILLA_COOKIE`.

## Запуск

```
npm start
```

Откройте http://localhost:3000

## Если список заданий не такой, как ожидалось

Структура ответа API работы-заданий не была заранее подтверждена. Приложение
эвристически ищет в JSON-ответе массивы, похожие на список заданий, и группирует
их по имени родительского поля — выбрать нужную группу можно в выпадающем списке
"Группа заданий" на странице. Включите чекбокс "показать сырой JSON", чтобы
посмотреть исходный ответ API и, при необходимости, поправить:

- `WORKZILLA_TASKS_PATH` в `.env`, если сами данные приходят с другого эндпоинта;
- сопоставление полей в `src/taskAdapter.js` (списки `TITLE_KEYS`, `SUM_KEYS` и т.д.),
  если конкретные названия полей в реальном ответе отличаются от предполагаемых.

## Безопасность

`.env` содержит вашу сессию/токен и никогда не должен коммититься — он уже добавлен
в `.gitignore`. Не публикуйте содержимое `.env` и не отправляйте его куда-либо.
